## 3. 图片来源与批量截图法

截图来自模拟器的**纯净截图模式**，不依赖手工操作：

1. 模拟器 URL 加 `?shot=1`：隐藏外壳/侧面板/顶栏，只渲染 640×480 屏幕画布（`body.shot` CSS）。
2. 用 `#<跳转名>` 直接跳到目标界面（模拟器 `applyJump()` 的 switch 分支，见下表）。
3. Chrome headless 截图：
   ```
   chrome --headless --disable-gpu --no-sandbox --force-device-scale-factor=2 \
     --window-size=680,<高> --screenshot=<输出.png> --hide-scrollbars \
     "file:///<模拟器路径>?shot=1#<跳转名>"
   ```
   （跳转名改变的是屏内状态，屏尺寸固定 640×480，window-size 略大即可。）

## 6. Word 版生产线（SOP）

流水线：`网页版内容` → `stage2/formatted-*.html`（doc-formatter 规范改写）→ `embed_images.py`（base64）→ `convert_doc.py` → `stage3/*.docx` → 复制到 `docs/manual/`。

### 6.1 运行命令

```bash
cd docs/manual/_pipeline
python gen_svg_png.py                                  # 仅当 SVG 图表有变动
python embed_images.py                                 # 每次改 HTML 后必跑
python <插件>/skills/html-to-doc/scripts/convert_doc.py \
  --html stage2/embedded-DX20S用户手册.html \
  --output stage3/DX-20S_用户手册_Word版.docx [--no-verify]
cp stage3/DX-20S_用户手册_Word版.docx ../DX-20S_用户手册_Word版.docx
```

### 6.2 doc-formatter 硬性规范（转换引擎实测约束，**必须遵守**）

1. 正文字体 `font-family` 第一项必须是 `"SimSun"`/`"宋体"`；字号 16px（小四）；`p{text-indent:2em}`。
2. 章节标题必须用 `<h1>~<h3>`（章=h1、节=h2、小节=h3），不能只用 class。
3. 封面标题**禁用 h1~h6**（用 `<p class="cover-title">` + 大字号），否则被目录收录为第一条。
4. 目录用 `<nav class="doc-toc">` **独占**一个 `<section role="cover">`；封面内容独占另一个 `role="cover"` section。
5. 目录条目 `<a href="#section-N">` 与标题 `id="section-N"` **一一对应**；条目文本=标题原文；含 h2 就必须有二级嵌套 `<ol>`；CSS 必须 `.toc-list{list-style:none}`。
6. 正文第一个 `<section data-page-restart="1">`（属性必须带值 `="1"`）。
7. 页脚页码写进 CSS：`@page { @bottom-center { content: "第 " counter(page) " 页"; } }`；封面命名页 `@page cover { @bottom-center { content: none; } }` + `section[role="cover"]{page:cover}`。
8. **CSS 注释里禁止出现 `@page` 字样**（会导致默认页眉规则静默失效）。

### 6.3 转换引擎坑位记录（踩过的雷，别再踩）

| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | 本地相对路径图片变 `[图片: …]` 文本占位 | 引擎不读本地文件 | **所有图片必须 base64 data URI**（`embed_images.py`） |
| 2 | `<1>静音`、`<7>音效设置` 等菜单编号整段消失 | 引擎把 `&lt;N&gt;` 反转后当 HTML 标签剥离 | 用中文角括号 `〈1〉`（U+3008/3009）代替 `<N>` |
| 3 | docx 中 `&amp;` 显示异常/verify 报含 `&` 段落 missing | 引擎不转义实体也不解码；verify 从 docx XML 取文本时不解码 `&amp;`（**误报**） | HTML 中写裸 `&`；verify 对含 `&` 段落的 C-1 报错属已知误报，可 `--no-verify`，但须手工确认 docx 内容完整 |
| 4 | SVG 图表不进 docx | 引擎只认位图 | 先用 Chrome headless 渲染成 PNG（`gen_svg_png.py`） |
| 5 | FAQ 用 `<details>` | Word 无折叠语义 | 改写为 `<p class="q">Q…</p>` + 普通段落 |

### 6.4 verify 通过标准（`convert_doc.py` 输出 JSON 解读）

- `preflight.passed = true`
- `structure.toc_field = true`、`pageref_count` = 目录条目数（28 = 15 个一级 + 13 个二级）
- `structure.heading_style_bound = "50/50"`（标题全绑定 Heading 样式；数量随章节增减）
- `structure.body_start1 = true`、`cover_toc_sectioned = true`、`pgNumType = true`
- `content.missing_count`：仅允许剩下"含 & 的已知误报"（≤9 条，见坑位 3）；其他 missing 必须排查

## 7. 增量更新 SOP（固件升级 / 新增功能时）

1. **读代码定位变更**：改了什么菜单项/设置项/默认值 → 对照 §2.1、§4 更新两张表。

## 8. 常见问答（维护时自查）

- **Q：新增一章怎么办？**
  A：网页版加 `<section id="sN">` + 侧栏目录链接；Word 版加 `<section><h1 id="section-N">` + 目录 `<li><a href="#section-N">`。注意 Word 版只有**第一个**正文 section 带 `data-page-restart="1"`。
- **Q：FAQ 要加条目？**
  A：两份都加。网页版用 `<details class="faq">`；Word 版用 `<p class="q">Q…</p>` + 段落。编号连续。
- **Q：改了默认值？**
  A：§4 表 + 速查表（第15章）+ 涉及章节正文的"出厂默认"列，三处同步。
- **Q：图片对不上？**
  A：确认模拟器对应跳转名的画面是否变化（如主题/亮度默认值变了会导致多张截图变化），重截后同步替换 `assets/` 同名文件（保持文件名不变，HTML 无需改）。

## 9. 两个重点功能的代码依据（2026-10-22 第二批升级）

### 9.1 蜂鸣器双规格（有源 / 无源）

- **开关**：`utilities.h` 宏 `BUZZER_PASSIVE`。当前固件已定义（=无源）。
- **无源**（本机）：LEDC PWM 驱动，`alert.cpp` 可播放真实音高旋律。提示模式页 `Menu.cpp` `renderAncMode()` 共 **7 项**，第 7 项进入音效设置两级页：
  - 第 1/2 页：按键音/确认音/取消音/返回音/错误音/上行预警/下行预警 7 类，各可选 高/中/低/默认（`tonePresetFreq[]={2093,1319,659,0}`，即 高/中/低/内置旋律）；
  - 第 2/2 页：其他提示音音调、开机音效开关（`boot_sound_en`）、开机音效风格（`boot_sound_type` 0/1/2=标准/欢快/经典）、返回。
- **有源**：GPIO 高低电平，只能固定音高鸣响。提示模式页仅 **6 项**（`Menu.cpp` 约 1277 行按宏裁剪），音效设置整页不可达——开机音效不可关、音调不可调；提示长短/提示音规范仍有效。
- **手册落点**：第 6.4 节（对比表）、FAQ Q21、第 6 章开头 7 项/6 项说明、§6.3 图 6-2/6-3 标注"无源专属"。
- **模拟器落点**：`S.SOUND_SET` 页面（sub=2 两级页）、`renderAncMode()` 7 项、侧栏"音调预设"试听面板、跳转名 `snd1`/`snd2`。

### 9.2 列车类型显示三态与新旧版分类规则

- **设置项**：`boards.cpp` `train_type_display`：0=关闭 / 1=旧版 / 2=新版（默认 2）。
- **分类函数**：`classifyTrain(cls, num, version)` 双版本逻辑：
  - **两版相同**：两位特殊字头（SY/AX/AB/DJ/DH/0J/00/SH/HX/HZ/JC/KJ）、纯数字车次（货运/单机/路用）；
  - **新版细分**：0X/0G/0T/0K/0D/0C/0S=回送、FX/FG/FT/FK/FD/FC/FS=折返、0N/0V/0Z/FN/FV/FZ=其他作业；客运 G/T/K/D/C/S/Z/N/V/Y/L/B 按号段细分为"直通/管内"，名称更短（如"直通高速动车"）；
  - **旧版**：G/D/C/Z/T/K/L/Y/S/X 粗分类（如"直通高速动车组"）；**X 字头旧版=货运班列（中欧班列），新版=新高速动车组**（复兴号），货运班列改到 B 字头。
- **等级徽标联动**：`gradeEnabled = train_grade_display && (train_type_display == 2)`——徽标**仅新版分类 + 车次等级标识启用**时显示；`getTrainGrade()` 返回 350/300/250/200/160/140/120/货/行包/动货，特殊作业列车返回空串（不显示徽标）；颜色默认主题按等级红→紫（`GRADE_COLORS`）。
